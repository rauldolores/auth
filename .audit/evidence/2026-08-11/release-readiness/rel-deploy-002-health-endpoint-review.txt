Gap-hunting (per this run's brief: would Next.js's own middleware/auth
gate intercept these despite the matcher exclusion?):

  The negative lookahead explicitly excludes the entire `/api` prefix —
  `/api/health` is categorically outside this middleware's matcher, so
  createAuthMiddleware() never runs for it. Confirmed by reading the
  matcher regex directly, not inferred.

apps/admin-panel: `find apps/admin-panel -maxdepth 1 -iname "middleware*"`
returns nothing — there is no middleware.ts source file in admin-panel at
all (only stale .next/ build artifacts from a prior build referencing a
middleware manifest, which is normal Next.js output even for a
middleware-less app — Next always emits a middleware-manifest.json,
empty or not). admin-panel's auth gating happens client/component-side
via dashboard-shell.tsx (confirmed by grep for AuthGuard/requireAuth
usage — the only match in admin-panel is dashboard-shell.tsx), which
wraps the React tree, not API route handlers — route handlers under
app/api/ are never touched by it. So admin-panel's /api/health is not
interceptable by any auth gate that exists in this app.

Automated verification: apps/auth-server/app/api/__tests__/health.test.ts
