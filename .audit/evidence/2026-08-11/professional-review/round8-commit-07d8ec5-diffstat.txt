    Add API route handler tests, closing the last open Phase 2 finding
    
    PQ-TECH-001 was the sole remaining item after seven rounds of Phase 2
    auditing today (security itself was independently live-exploit-tested
    and closed across migrations 0025-0030) — zero test coverage existed
    for any Next.js API route handler in apps/auth-server.
    
    95 tests across all 12 route files. Thorough coverage on the three
    highest-risk routes:
    - organization-members: full wouldRemoveLastOwner() branch coverage
      (blocks suspending/removing the org's sole active Owner, allows it
      with a second active Owner present, allows it freely for non-Owners).
    - platform-admins: the authorizePlatformAdmin() gate on all three
      verbs, and the last-platform-admin block on DELETE.
    - invitations/accept: expired/used/wrong-email rejection, successful
      accept, and a regression test for commit 717bf03's fix — when the
      role-grant upsert fails, the route now returns 500 and never touches
      the invitation's accepted_at, confirmed by asserting the invitations
      table is only ever queried once.
    
    Lighter but real coverage (happy path + key error/validation branches)
    on the remaining 9 routes.
    
    apps/auth-server had no test infrastructure — added vitest + a
    vitest.config.ts resolving the app's "@/*" path alias (needed since
    these route handlers and their vi.mock() calls use it), matching the
    version already used in packages/auth-sdk/next-sdk.
    
    All 145 tests across the monorepo pass; build/lint/typecheck clean.
